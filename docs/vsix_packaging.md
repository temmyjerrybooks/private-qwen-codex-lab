# VSIX Packaging

Borger uses project-local `@vscode/vsce` for repeatable local packaging.

## Package Locally

```powershell
cd apps/vscode-extension
npm.cmd install
npm.cmd run check-types
npm.cmd run compile
npm.cmd run package
```

Expected output:

```text
apps/vscode-extension/borger-vscode-agent-0.13.0.vsix
```

The package script does not publish to the Marketplace.

Phase 14 observed a generated package size of about 4.37 MB:

```text
apps/vscode-extension/borger-vscode-agent-0.13.0.vsix
```

The package includes compiled `dist/` output, media assets, runtime dependencies, README, changelog, license, and package metadata. Raw `src/` files are excluded; webview CSS is copied into `dist/webview/styles.css` during compile.

## Install Locally

```powershell
code --install-extension apps/vscode-extension/borger-vscode-agent-0.13.0.vsix
```

If the package version changes, install the `.vsix` file generated by `npm.cmd run package`.

You can confirm the installed extension with:

```powershell
code --list-extensions --show-versions | Select-String borger
```

`vsce` may warn that the package contains many JavaScript dependency files. That is expected until the extension is fully bundled; do not remove `node_modules` from the package unless the extension runtime has been bundled and tested.

## Global vsce Alternative

The repo already includes `@vscode/vsce` as a dev dependency. If needed, you can also install the packager globally:

```powershell
npm.cmd install -g @vscode/vsce
```

Then run:

```powershell
cd apps/vscode-extension
vsce package
```
